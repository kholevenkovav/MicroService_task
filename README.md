## 1. Постановка задачи

- **Цель:** обнаружение аномалий в температуре морозильных камер (два `io_id`).
- **Подход:** методы без учителя (IsolationForest, One-Class SVM, LOF, PCA,
  PCA-IF, PCA-OCSVM), скользящие окна по минутной сетке, кодирование времени.
- **Оценка:** по размеченному датасету (`annotated_dataset.csv`, поле `anomaly` ∈ {0,1}).
  Считаются ROC-AUC, F1, Accuracy, Precision, Recall.

## 2. Архитектура системы

Сервисы и их роли:

- **Collector (FastAPI):** отдача батчи данных из CSV (сырая/аннотированная серия),
  нормализация колонок.
- **Storage (FastAPI + SQLite):** хранение «запусков» (`runs`) и метрик (`metrics`).
- **ML (FastAPI, sklearn):** - обучение и оценка моделей, агрегация метрик.
- **Web Master (API-gateway):** сценарии верхнего уровня, агрегация данных из ML/Storage.
- **Visualization (Dash):** веб-дашборд для просмотра лучшей конфигурации и метрик по выбранному `io_id` и модели.

Коммуникации - REST. Конфигурации - YAML. Контейнеризация - Docker compose.

```
services/
  collector/ - /batch
  storage/ - /runs/*, /metrics/*
  ml/ - train_evaluate, status
  webmaster/ - /scenarios/*
  visualization/ - дашборд http://localhost:8014
```

## 3. Данные

В корне проекта создана папка `./data` и лежат:

- `freezer_temperature.csv` — сырая минутная телеметрия (колонки:
  `event_timestamp, io_id, value, value_min, value_max`). `value_min/max` не нужны.
- `annotated_dataset.csv` — размеченные точки (те же колонки + `anomaly`).

Collector будет нормализовать имена колонок и удалять `value_min/value_max`.

## 4. Методика обучения и оценки (ML)

Что будет содержать main.py:
- **Ресэмплинг:** интерполяция/выравнивание по минутной сетке.
- **Скользящие окна:** 5, 10, 15, 30, 60 минут; признаки окна: mean/std/min/max/median/var/trend/q25/q75.
- **Кодирование времени:** `one_hot` (час/минута), `sin_cos` (час, минута),
  `cyclic` (сезонное кодирование), `sin_cos_cyclic` (комбинация).
- **Сплиты:** `70_30`, `50_50`, `30_70` — в сутках, суммарно 100.
- **Сдвиги:** 5 равномерных сдвигов 100-дневного окна (циклически).
- **Модели:** IF, OCSVM, LOF, PCA-reconstruction, PCA-IF, PCA-OCSVM.
- **Метрики:** ROC-AUC, F1, Accuracy, Precision, Recall.

## 6. Сценарии использования (минимальный набор)

Ниже - минимальные сценарии работы через **Web Master** (`/scenarios/*`):

- **Проверить, что сценарный сервис жив и готов:**
  - `GET /scenarios/status`

- **Узнать доступные `io_id` (для выбора серии):**
  - `GET /scenarios/io_ids`

- **Посмотреть сетку параметров экспериментов (что вообще можно гонять):**
  - `GET /scenarios/param_grid`

- **Посмотреть датасет (служебная выдача для проверки/эмуляции/preview):**
  - `GET /scenarios/dataset`

- **Запустить единичную оценку (без сохранения в Storage):**
  - `POST /scenarios/evaluate_once`  
  - Тело запроса: JSON с параметрами прогона (ориентируйтесь на `/scenarios/param_grid` и Swagger `/docs`).

- **Запустить оценку и сохранить результат (run + метрики):**
  - `POST /scenarios/evaluate_and_store`  
  - Тело запроса: JSON с параметрами прогона (ориентируйтесь на `/scenarios/param_grid` и Swagger `/docs`).

- **Посмотреть метрики (как правило, агрегированные/последние):**
  - `GET /scenarios/metrics`

- **Посмотреть список запусков (runs):**
  - `GET /scenarios/runs`

- **Обучить модель (если выделен отдельный шаг train):**
  - `POST /scenarios/train_model`  
  - Тело запроса: JSON с параметрами обучения (см. Swagger `/docs`).

## 7. API (используемое)

### Web Master (API-gateway)
- `GET  /scenarios/status` - статус сервиса
- `GET  /scenarios/io_ids` - список доступных `io_id`
- `GET  /scenarios/param_grid` - доступные конфигурации/параметры экспериментов
- `GET  /scenarios/dataset` - выдача датасета/среза для проверки
- `POST /scenarios/evaluate_once` - оценка одного прогона без сохранения
- `POST /scenarios/evaluate_and_store` - оценка и сохранение (run + метрики)
- `GET  /scenarios/metrics` - метрики
- `GET  /scenarios/runs` - список runs
- `POST /scenarios/train_model` - обучение модели
